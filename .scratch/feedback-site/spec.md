## Problem Statement

가람중학교 2학년 과학 「전기와 자기」 수업에서 학생은 수업 후 이해한 내용을 글로 제출하고, 선생님은 학생별 글을 읽어 피드백을 남겨야 한다. 현재 학생의 최초 제출 글, 선생님 피드백, 학생의 수정 글을 한곳에서 이어서 확인할 수 있는 흐름이 필요하다.

## Solution

학생과 선생님이 각자의 역할에 맞는 화면을 사용하도록 하나의 웹 페이지 안에서 화면을 전환한다. 학생은 수업 제목과 오늘의 질문을 확인하고 3~10문장으로 답변을 제출한다. 선생님은 학생별 제출 상태와 확인하지 않은 글 수를 보고, 학생의 글에 2~3문장 피드백과 격려 문구를 저장한다. 학생은 피드백을 확인한 뒤 최초 글과 피드백을 보면서 글을 수정해 재제출한다.

## User Stories

1. 학생으로서 수업 제목을 보고 싶다. 그래야 내가 답해야 할 수업 주제를 알 수 있다.
2. 학생으로서 오늘의 질문을 보고 싶다. 그래야 질문에 맞춰 답변을 작성할 수 있다.
3. 학생으로서 내 이름을 입력하고 싶다. 그래야 선생님이 내 제출 글을 구분할 수 있다. (AI 제안)
4. 학생으로서 3~10문장의 답변을 작성하고 싶다. 그래야 수업에서 요구한 분량으로 이해한 내용을 표현할 수 있다.
5. 학생으로서 답변을 제출하고 싶다. 그래야 선생님이 내 글을 확인할 수 있다.
6. 학생으로서 답변 제출이 완료되었는지 보고 싶다. 그래야 내 글이 저장되었는지 알 수 있다.
7. 학생으로서 제출 전에는 답변을 수정할 수 있고 제출 후에는 제출 상태를 확인하고 싶다. 그래야 제출 여부를 혼동하지 않을 수 있다.
8. 선생님으로서 학생 목록을 열고 싶다. 그래야 여러 학생의 제출 상황을 한눈에 확인할 수 있다.
9. 선생님으로서 학생 이름을 보고 싶다. 그래야 특정 학생의 글을 구분할 수 있다.
10. 선생님으로서 학생별 미제출 상태를 보고 싶다. 그래야 아직 글을 내지 않은 학생을 알 수 있다.
11. 선생님으로서 학생별 제출 완료 상태를 보고 싶다. 그래야 최초 제출 글을 확인할 학생을 알 수 있다.
12. 선생님으로서 학생별 피드백 완료 상태를 보고 싶다. 그래야 피드백을 남긴 학생을 구분할 수 있다.
13. 선생님으로서 학생별 수정 제출 상태를 보고 싶다. 그래야 피드백을 반영해 다시 제출한 글을 알 수 있다.
14. 선생님으로서 학생별 확인하지 않은 글 수를 보고 싶다. 그래야 아직 확인하지 않은 제출 글을 우선 처리할 수 있다.
15. 선생님으로서 학생을 선택해 학생 이름과 제출 글을 보고 싶다. 그래야 학생별로 내용을 읽을 수 있다.
16. 선생님으로서 제출 시간을 보고 싶다. 그래야 학생이 글을 제출한 시점을 알 수 있다.
17. 선생님으로서 학생 글에 2~3문장 피드백을 입력하고 싶다. 그래야 학생의 글에 구체적인 도움을 줄 수 있다.
18. 선생님으로서 학생에게 격려 문구를 남기고 싶다. 그래야 피드백과 함께 학생의 다음 시도를 격려할 수 있다.
19. 선생님으로서 피드백과 격려 문구를 저장하고 싶다. 그래야 학생이 나중에 확인할 수 있다.
20. 선생님으로서 학생의 수정 전 글과 수정 후 글을 함께 보고 싶다. 그래야 피드백을 반영해 무엇이 달라졌는지 확인할 수 있다.
21. 학생으로서 선생님 피드백을 열어 보고 싶다. 그래야 내 글에 대한 조언을 확인할 수 있다.
22. 학생으로서 내가 처음 제출한 글을 다시 보고 싶다. 그래야 수정할 때 원래 생각과 비교할 수 있다.
23. 학생으로서 선생님의 격려 문구를 보고 싶다. 그래야 피드백의 격려 내용을 확인할 수 있다.
24. 학생으로서 제출 글을 수정하고 싶다. 그래야 선생님의 피드백을 반영할 수 있다.
25. 학생으로서 수정한 글을 재제출하고 싶다. 그래야 선생님에게 수정 결과를 전달할 수 있다.
26. 학생으로서 수정 제출 완료 상태를 보고 싶다. 그래야 수정 글이 저장되었는지 알 수 있다.

## Implementation Decisions

- 기능 이름(feature-slug)은 `feedback-site`로 한다.
- 대상은 가람중학교 2학년 과학 「전기와 자기」의 한 수업으로 한정한다.
- 학생 화면과 선생님 화면은 별도의 페이지로 만들지 않고, 하나의 `index.html` 안에서 현재 역할과 화면 상태에 따라 바꿔 보이게 한다.
- 첫 진입 시 학생 또는 선생님 역할을 선택하는 간단한 진입 화면을 둔다. 학생 화면은 바로 열고, 선생님 화면은 관리자 비밀번호를 입력해야 연다. 복잡한 로그인이나 인증은 구현하지 않는다.
- 선생님 화면은 관리자 비밀번호를 입력해야 열린다.
- 실습용 관리자 비밀번호는 `teacher-demo`로 한다.
- 관리자 비밀번호를 입력하기 전에는 학생 글과 선생님만 보는 내용이 화면에 보이지 않는다.
- 학생은 답변을 제출하기 전에 이름을 입력한다. 이름은 학생 제출 자료를 구분하기 위한 값으로만 사용한다. (AI 제안)
- 학생 목록은 저장된 학생 제출 자료를 기준으로 표시한다. 아직 제출하지 않은 학생 상태를 표시하기 위해 수업에서 사용하는 학생 목록은 브라우저 저장 데이터에 함께 둔다. 학생 목록을 별도로 관리하는 기능은 만들지 않는다. (AI 제안)
- 데이터는 브라우저의 `localStorage`에 저장하고 데이터베이스, 서버 API, 외부 인증은 사용하지 않는다.
- 저장 데이터에는 학생 식별 정보, 최초 제출 글, 최초 제출 시간, 피드백, 격려 문구, 수정 제출 글, 수정 제출 시간, 피드백 확인 여부를 포함한다. (AI 제안)
- 학생의 최초 제출 전 상태는 `미제출`, 최초 글을 제출한 상태는 `제출 완료`, 선생님이 피드백을 저장한 상태는 `피드백 완료`, 학생이 수정 글을 재제출한 상태는 `수정 제출`로 표시한다.
- 학생이 피드백 화면을 열면 해당 학생의 확인하지 않은 글 수를 줄이고 피드백을 확인한 것으로 저장한다. (AI 제안)
- 답변은 문장 수가 3~10개일 때만 제출할 수 있게 한다. 문장 수는 마침표, 물음표, 느낌표 등 문장 끝 표시를 기준으로 단순하게 계산한다. (AI 제안)
- 피드백은 문장 수가 2~3개일 때만 저장할 수 있게 한다. 문장 수 판정 방식은 학생 답변과 동일하게 적용한다. (AI 제안)
- 답변, 피드백, 학생 이름처럼 필수 값이 비어 있으면 저장하지 않고 입력 화면에 안내 문구를 표시한다. (AI 제안)
- 선생님 화면에서는 학생 목록에서 학생을 선택하면 해당 학생의 상세 화면으로 이동한다. 상세 화면에는 학생 이름, 제출 글, 제출 시간, 피드백 입력 칸, 격려 문구 입력 칸, 저장 버튼, 수정 전후 글을 표시한다.
- 학생 화면에서는 제출 화면과 피드백 확인·수정 화면을 같은 페이지 안에서 전환한다. 피드백이 저장된 뒤에만 선생님 피드백, 격려 문구, 수정 입력 영역을 보여 준다.
- 제출 글과 수정 글은 원문을 보존한다. 수정 제출 시 최초 제출 글을 덮어쓰지 않고 수정 전후를 나란히 확인할 수 있게 한다.
- 화면 전환에 필요한 상태와 저장 데이터만 관리하며, PRD에 없는 검색, 알림, 통계, 다운로드, 외부 공유, 여러 수업 관리, 학생 간 글 보기, 회원가입과 복잡한 로그인은 구현하지 않는다.
- 자동 테스트 도구는 사용하지 않는다. 기능은 브라우저에서 직접 화면과 저장 결과를 확인한다.

## Testing Decisions

- 테스트 대상은 사용자가 브라우저에서 경험하는 화면과 상태 변화로 한정한다. 내부 함수나 저장 구현의 구조를 별도로 검증하지 않는다.
- 학생 흐름을 수동으로 확인한다: 역할 선택 → 이름과 3~10문장 답변 입력 → 제출 → 제출 완료 상태 확인 → 피드백 확인 → 최초 글·피드백·격려 문구 확인 → 수정 글 작성 → 재제출 → 수정 제출 상태 확인.
- 선생님 흐름을 수동으로 확인한다: 역할 선택 → 학생 목록 열기 → 학생 이름과 미제출·제출 완료·피드백 완료·수정 제출 상태 확인 → 확인하지 않은 글 수 확인 → 학생 글 열기 → 제출 글과 제출 시간 확인 → 2~3문장 피드백과 격려 문구 입력 → 저장 → 수정 전후 글 확인.
- 경계 조건을 수동으로 확인한다: 답변이 3문장 미만 또는 10문장 초과일 때 제출되지 않는지, 피드백이 2문장 미만 또는 3문장 초과일 때 저장되지 않는지, 필수 입력이 비었을 때 안내되는지 확인한다.
- 브라우저를 새로고침한 뒤에도 `localStorage`에 저장된 학생 글, 피드백, 격려 문구, 상태가 유지되는지 확인한다.
- 별도의 자동화 테스트, 테스트 러너, 테스트 프레임워크는 추가하지 않는다.

## Out of Scope

- 회원가입과 복잡한 로그인
- 여러 수업 또는 여러 과목 관리
- 학생끼리 서로의 글 보기
- 별도 통계 기능
- 다운로드 기능
- 알림 기능
- 검색 기능
- 외부 공유 기능
- 데이터베이스와 서버 저장
- 별도 페이지 파일, 별도 프런트엔드 라우터, 자동화 테스트 도구
- PRD에 정의되지 않은 학생·선생님 기능

## Further Notes

- 모든 화면과 화면 전환은 하나의 `index.html`에서 처리한다.
- 기능 확인은 브라우저에서 직접 수행한다.
- 브라우저의 `localStorage`를 삭제하면 실습 데이터가 초기화된다. 초기화 전용 사용자 기능은 추가하지 않는다. (AI 제안)
